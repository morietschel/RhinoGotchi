# RhinoGotchi

A RhinoCommon plugin for **Rhino 8 and Rhino 9 (Windows and Mac)**, based on McNeel's
[Your First Plugin](https://developer.rhino3d.com/guides/rhinocommon/your-first-plugin-windows/) guide.

## RhinoGotchi panel: What Made This?

The **RhinoGotchi** side panel has a daily game for learning Rhino commands.
Each of five rounds draws real geometry in a perspective viewport: the starting
curves or solids in orange, and the result in blue. Pick the command that made it
(Loft, Revolve, Sweep1, Pipe, FilletEdge, Contour...). Every answer explains the
command and has **Try** (runs it in Rhino) and **Help page** buttons.

The panel also has a **Command Library** with three sub-categories: **Curves**,
**Solids** and **Transform** (113 commands). Each command has its icon (from
`Rhino/RhinoIcons/svg`), its description (from `Rhino/rhino_commands_all.csv`), a
**Try it!** button and a help link. Core commands also have a step-by-step
**How it works** demo drawn in the viewport: numbered dots for each pick, orange for
the starting geometry, blue for the result. **Try it on the demo setup** adds the
starting geometry to your model (undoable) so you can run the real command on it.
Demos live in `Content/CommandDemos.cs`; adding one is a few lines.

Each command page also shows **where to find it**: which tab or sidebar button (and
flyout) holds it, drawn as a copy of that toolbar with the button highlighted. The map
is generated by `tools/Generate-ToolbarMap.ps1` from Rhino's `default.rui` into
`Content/ToolbarMap.g.cs`. **What's next** links to commands that usually follow, and
**Recipes** (`Content/Recipes.cs`) show how commands string together, stage by stage
(e.g. Line → Join → ExtrudeCrv → FilletEdge).

## Build Order game

A second daily game: the viewport shows a finished object built from a recipe, and you
pick its commands from a shuffled bank (with decoys) in the right order. Slots turn teal
(right place), gold (used elsewhere) or gray (not used); four tries and one hint. Then
watch it get built, step by step.

Nothing is added to your model, and your view is restored when you leave the game.
Everyone gets the same rounds each day; daily scores and streaks are saved in the
plugin settings, and practice rounds don't count. The panel home page also has a
tip of the day, stats, and a reset action.

## Leaderboard

Each board shows every player's best round in that game, and the **Global** board adds a
player's bests together. Players pick a public name and a small icon to appear.

| Game | Score for a round |
| --- | --- |
| What Made This? | 20 per right answer (max 100) |
| Build Order | 100 for a first-try solve, 20 fewer per extra try, 10 fewer with the hint |
| Deep Cut | the round's points (up to 5,000) |

When a round, daily or practice, beats the player's best for that game, the new best is
saved and pushed straight away. Bests and the profile are kept in the plugin settings and
pushed in full each time, so a failed upload is made up for by the next one.

**One-time setup.** The backend is a free Firebase Realtime Database (Spark plan, no card):

1. [console.firebase.google.com](https://console.firebase.google.com) → Add project → Build → Realtime Database → Create database.
2. Rules tab → paste `firebase/database.rules.json` → Publish.
3. Copy the database URL (like `https://my-project-default-rtdb.firebaseio.com`) into
   `DatabaseUrl` in `Core/Leaderboard.cs`. While it is empty the leaderboard stays offline.
   For a debug session you can set the `RHINOGOTCHI_LEADERBOARD_URL` environment variable instead.

There is no login: anyone can write a row, so scores can be faked. The rules only limit
the shape and size of what is written.

**Data layout** (plain REST, so other games can share the same database):

```
boards/{board}/{playerId} = { "s": score, "n": name, "i": iconVersion, "t": serverTime }
icons/{playerId}          = "base64 PNG or JPEG, 48×48"
```

`board` is a game key or `global`. To add a game: add its key to `Games` in
`Core/Progress.cs` and call `Leaderboard.Report(game, score)` when a round ends.
`Core/LeaderboardClient.cs` and `Core/MiniJson.cs` have no Rhino dependencies and can be
copied into another project as is.

## Deep Cut game

A third daily game: a real Rhino model (from a McNeel forum topic) appears alone in the
viewport. Orbit it, then name a command that was used to build it; you have 30 seconds and
one guess per model, five models a day. Whatever you type resolves to a real command. An
OpenAI model (Decisions API, `gpt-6-luna`) looks at a picture of your viewport and answers
two things: was the command used, and how rare is it. Points = 1000 x rarity, and only if it
was used.

- The 50 models are bundled as `DeepCut/Models/*.dcm` next to the `.rhp` (5 MB in total):
  gzipped, quantized render meshes and curves. The format is documented in
  `Content/DeepCutModels.cs`; `DeepCut/models.tsv` lists each model's forum topic.
- The judge needs an OpenAI key. A short-lived one is hard-coded in `Core/ApiKey.cs` and
  ships with the repository. Once it expires or is rejected, the game asks the player for
  their own, which is also editable under
  **Settings** on the home page and stored in the plugin settings.

Every game is a row on the **Games** tab: the four dailies (Build Order, What Made This?, Deep Cut,
Blocked!), then the level games with a tag that counts cleared levels.

| Game | What it is | Code |
| --- | --- | --- |
| Water Run | Gumball levels, see below | `Water/` |
| Drone School | Mouse lessons: zoom, pan, orbit, fly | `Drone/` |

## Water Run (Gumball levels)

Thirteen levels that teach the Gumball: water pours from a fountain and has to reach the goal, and
the only tool is the Gumball. Open it from **Games → Water Run**, or type `GotchiWater`.

| # | Level | | Gumball part |
| --- | --- | --- | --- |
| 1 | Slide the lid | 2D | Move arrows |
| 2 | Zigzag | 2D | Move and rotate two boards, over and under a roof |
| 3 | Fill, carry, pour | 2D | The bucket: fill it, carry it up, tip it |
| 4 | The third arrow | 3D | Moving along all three arrows |
| 5 | Turn the corner | 3D | The flat rotate arc, then a 3D move |
| 6 | High water | 3D | Bucket: the goal is above the tap |
| 7 | Out of thin air | 3D | Extrude a curve |
| 8 | Swing the boom | 3D | Moving the Gumball itself (new pivot) |
| 9 | Stretch first | 3D | Scale handles · red plate |
| 10 | Along the slope | 3D | Align to Object · red block |
| 11 | Around the pillar | 3D | Alt-drag to copy, turn the copy · red pillar |
| 12 | Bucket relay | 3D | Chute under a red roof, bucket over a red wall |
| 13 | The long way up | 3D | Hard: copy and turn a chute to a tower under a red roof, feed it by bucket, two trips |

- **Playing:** starting a level adds its pieces to the open model (use an empty file), turns the
  Gumball on and locks the gray and stone pieces. Orange pieces move. Any other command that
  changes the model is undone. Every drop that reaches the goal sparkles, the goal and the
  progress bar fill up, and the level is won when the goal amount is reached. The water never
  runs out.
- **2D levels** fill the Front view; the water stays in one plane and a move that takes a piece
  out of that plane is undone. From level 4 the game is real 3D in the perspective view, with no invisible panes.
- **Red is deadly:** if water, or a piece the player can move, touches a red hazard, the level
  is lost at once and has to be restarted.
- **Editing:** **Edit level** unlocks everything and lets every Rhino command through. Add
  sources (a point drips, an arrow is a jet), goals and hazards, mark pieces fixed or movable,
  change the flow, goal amount and drop size, then **Save level**.
- **Where levels live:** the built-in scenes are code in `Water/WaterLevels.cs`. A saved level is
  `levels/water/level-NN.3dm` (the scene) and `level-NN.txt` (title, lesson, instruction, target,
  rate, dropsize, flat as `key=value` lines) and replaces the built-in one. They are copied
  next to the `.rhp` as `WaterLevels/` on build. **Revert to built-in** deletes the saved pair.
- **Red is forgiving of splashes:** a stray drop on red only sizzles; twelve drops lose the level.
- **Buckets:** moving or turning a piece takes the water in it along, so a bucket can be filled at
  the tap, carried anywhere (also up) and tipped out.
- **Code:** `Water/WaterCore.cs` is the physics and `Water/WaterLevels.cs` the levels; neither uses
  Rhino. `Water/WaterLab.cs` reads the model and draws the water, `Water/WaterGame.cs` runs the
  levels and their rules.
- **Testing levels:** `dotnet run -c Release --project tools/WaterTest -- -jitter 20` plays every
  level without Rhino: left alone it must neither win nor lose, its built-in solution must win, and
  it must still win most of the time when the pieces are placed sloppily. Add a level number to run
  one, and `-render <folder>` for pictures.

One project builds two targets:

| Target | Runs in |
| --- | --- |
| `net7.0` | Rhino 9 Mac (.NET 10), Rhino 8 Mac, Rhino 8 Windows (default .NET Core runtime) |
| `net48` | Rhino 8 Windows started with `SetDotNetRuntime` = .NET Framework |

## Requirements

- .NET SDK 7 or newer (`dotnet --list-sdks`)
- Rhino 8 or Rhino 9

## Build

```bash
dotnet build RhinoGotchi.sln -c Release
```

Output:

- `src/RhinoGotchi/bin/Release/net7.0/RhinoGotchi.rhp`
- `src/RhinoGotchi/bin/Release/net48/RhinoGotchi.rhp`

## Package Manager (Yak)

```bash
./tools/build-yak.sh
```

builds the two packages for Rhino's Package Manager into `dist/`, under the name **Rhinogotchi**:

| Package | Installs in | Contains |
| --- | --- | --- |
| `rhinogotchi-<version>-rh8_0-any.yak` | Rhino 8, Windows and Mac | `net7.0/` and `net48/` |
| `rhinogotchi-<version>-rh9_0-any.yak` | Rhino 9, Windows and Mac | the `net7.0` build |

The version comes from `<Version>` in `RhinoGotchi.csproj`; the name, description and icon from
`yak/`.

To publish, raise the version (a published version can't be replaced), then:

```bash
./tools/yak-login.sh        # once: sign in with your Rhino account
./tools/deploy.sh --test    # optional rehearsal on test.yak.rhino3d.com
./tools/deploy.sh           # build, confirm, push both packages
```

On Windows, run the scripts from Git Bash.

## Load and run

- **Mac:** drag `bin/<Config>/net7.0/RhinoGotchi.rhp` onto the Rhino 8 window,
  or run `PluginManager` → Install.
- **Windows:** drag the `.rhp` that matches your runtime onto Rhino 8
  (`net7.0` by default, `net48` if you switched with `SetDotNetRuntime`).

The plugin loads at startup and registers the **RhinoGotchi** panel. Type `RhinoGotchi` to open it,
or open it from the panel tabs menu.

## One sidebar: Learning and Games

Everything lives in the single **RhinoGotchi** panel: clean black and white with a muted
green for right answers, orange for selection and streaks, and Duolingo-style chunky
buttons and cards. It follows Rhino's dark mode (the ink inverts) and reflows when the
panel is resized; on a wide panel the lessons keep a centered column.

- **Gotchi** is the 1-bit pixel rhino, built the Wardrobe Lab way (`Resources/Pet`,
  `UI/MascotWardrobe.g.cs`): idle, celebrate, sleeping and fainted poses, and an outfit of
  **one face item, one hat and one clothing item** drawn at each pose's placement points.
  The outfit stays on through hops and the "feeding time" animation (grass, leaf, branch,
  twig, apple, banana, watermelon) when you tap Gotchi or finish a lesson.
- **Home:** Gotchi's card (it breathes and naps when you haven't played today), with chips
  for your streak, unlocks and questions solved. Below it, two tabs: **Learning** (Learn
  Projects, Learn Commands, tip of the day) and **Games** (the other games). Rows show progress
  (3/12, DONE) once something is started; there are no PLAY tags.
- **Bottom bar:** Home · Trophies.
- **Trophies:** the leaderboard at the top, then the **wardrobe room**: Gotchi eats on a
  loop in its outfit, with **Surprise me** and **Undress**, and Face · Hat · Clothes tabs.
  Each tile shows Gotchi with that item swapped in; locked ones show how to unlock them.
  Below: every achievement and your daily-game stats.
  - **Face** (free): snorkel mask, visor, ninja mask, shutter shades.
  - **Hats:** First Steps (first lesson), Par Excellence (win a daily), Hot Streak (3 days in
    a row), Scholar (all 10 levels), Order Up (5 Build Order wins), Know-It-All (5 What Made
    This? wins), Deep Roots (win Deep Cut), Workaround (win Blocked!), Clean Sweep (all four
    dailies in one day).
  - **Clothes:** big gold chain (placement test), leather jacket (flawless lesson), jeans in
    both styles (5 levels), bow + pearls (1,000 XP).
  - New unlocks also appear on the lesson-complete screen with a **Wear it** button.
- **Leaderboard icon:** My profile → **Use my Gotchi** draws your dressed Gotchi as your icon.

## Learn Projects

The first row on the Learning tab (or type `Gotchi`). Three projects, in this order:

| Project | What it is | Clean-up |
| --- | --- | --- |
| **Build a road** | Rhino on the Street: draw the street (Curve), then the archway (Line, Arc). Plays in one maximized Perspective viewport; your layout and camera come back afterwards. | Everything it made is deleted when the whole game ends (a few seconds after the end card, or when you quit). |
| **Build a facade** | Fin Facade: six levels, one box wrapped in fins. | The levels build on each other, so it clears when you leave it. A finished facade is remembered (DONE). |
| **Build a building** | The twelve Klosterneuburg levels (below), opened straight at your next level. The Klosterneuburg model is built into the plugin and added to the document when you start. | Each level's geometry (inputs, guides and what you made) is deleted when you move on; leaving removes the model again. |

Only what a game made is deleted: anything already in the document stays. The other games
clear the same way: Blocked! a few seconds after a challenge is solved or when you leave, Water
Run when a level ends or you leave (not while editing a level), Drone School removes its drone,
and the puzzle games only ever draw previews.

Build a building needs a document in metres: an empty document is switched to metres; one in
other units with work in it asks you to start a new metre file.

## The Learning Campaign (hidden)

The ten-level campaign and the placement test are no longer on the Learning tab. The code stays:
it runs Build a building.

- **First run:** pick *Start from scratch* (Level 1) or *Find my level*, a
  placement test with 2 questions per level (up to 20), easiest first. It stops at the
  first miss, and that question's level is where you start. Every level below it
  is marked done.
- **Level map:** FinGotchi's look. The pixel rhino says what's next, a cream *Your level*
  card shows where you are, and each chapter is a row of numbered tiles: black when done,
  orange-edged when you can play it, grey when locked. You can retake the placement test or
  go back to the start screen any time.
- **Look and feel:** the whole campaign follows FinGotchi: white paper, slab-serif headings,
  pill buttons, cream cards, yellow "do this now" buttons with a hard black shadow, and the
  animated pixel rhino (it dozes after 5 s without a click or key press).
- **Progress** (finished levels, XP, placement taken, streak, hats) is saved in the
  plugin's settings, per user on this machine, so it survives a Rhino restart. A lesson
  is saved as soon as you reach its complete screen.

Levels live in `src/RhinoGotchi/Lessons/LessonCatalog.cs` (10 levels): Curves,
Solids (includes the Box build level), Surfaces, Sweeps & Pipes, Editing Solids,
Curve Tools, Transforms, Surface Tools, Advanced Solids, Mastery.

Three question types, from easy to hard:

| Type | Card | Used from |
| --- | --- | --- |
| Pick the icon | "Which one of these is Sweep2?" + 4 icons | Level 1 |
| Name it | One big icon + 4 look-alike names | Level 3 |
| Solve the task | A modeling task in words + 4 icons, no names | Level 4 |

The placement test asks each level's first two questions, so it ramps from
pick-the-icon to scenarios and shows an EASY / MEDIUM / HARD marker.

### The Klosterneuburg chapter

A chapter on the campaign map, after the ten main levels: **twelve commands, one building**,
the Klosterneuburg pavilion (`V18 P020 - Klosterneuburg_Final.3dm`, metres). It is open from
the start, played in order, and left out of the placement test; finished levels earn XP.

**The model is in the repo:** open `Rhino/Models/Klosterneuburg_light.3dm` (2.1 MB) before
playing the chapter. It is a light copy of the 64 MB original made for uploading:

- The geometry the tutorials build from stays exact NURBS: the roof surface, the ramp, the
  east glass panel and the stair handrail.
- Everything else (mainly the 1,375 timber beams, plates and dowels) is a coarse mesh,
  merged into one object per layer. The layer names and tree are unchanged, so every
  tutorial still finds its reference layers.
- Left out: the layout sheets, the work layer and clipping plane, and render meshes.

All twelve levels were checked to start from this copy using the real model, not the
stand-in. Use the full original if you need to edit the building itself.

| Part | Levels, easiest first |
| --- | --- |
| Details | 1 BooleanDifference (steel plate) · 2 Pipe (handrail) · 3 OffsetSrf (glass) · 4 ArrayPolar (beam setting-out) |
| Structure | 5 ArrayCrv (balustrade) · 6 Contour (roof slices) · 7 Intersect (rib profile) · 8 Sweep1 (edge beam) |
| Surfaces | 9 Sweep2 (ramp) · 10 FlowAlongSrf (joists) · 11 Loft (roof) · 12 NetworkSrf (roof) |

Each level is one build, played like FinGotchi, with no quiz cards. Pressing a tile sets the
level up straight away:

- **Level page (panel):** the chapter's tiles, an animated key-axon demo that loops through
  the steps (the step being shown lights up), the cream lesson card ("LEVEL n OF 12", the
  command, one line, "★ first try possible" or "misses n / 3"), the yellow **Run** card that
  starts the command with the right objects already picked (e.g. `_SelID {Plate}
  _BooleanDifference`), a hint, the steps, the ways to run it, your commands, and
  **‹ Map** / **Next ›**. When you solve it (or after three misses) the pet takes over the
  demo area.
- **Viewport HUD:** the lesson card top left, the dark live-check card top right, a yellow
  "type it up here" callout, the pet with a speech bubble, and the commands you ran. Yellow
  numbered marks show where to click, with locked snap points under them; Point and End
  snaps are on while the level runs.
- **Live check:** after every command, ✓/✗ per check with a hint on the first failing one,
  a bonus star (e.g. "Cap it into a closed solid") and your misses (a command that changed
  the model without solving the level; Undo, Redo and Delete don't count).
- **Flow:** **Next ›** opens once the level is solved and goes straight to the next level.
  After the last one the chapter's Done page ("Splendid.", how many were first try) leads
  back to the campaign map.

The original model is never changed: reference objects are found by layer path under
`0_3DMODEL` and only copies are used, all tutorial geometry goes under
`RhinoGotchi Tutorials::NN Command` (Input / Result / Checks), roof copies are lifted 4 m
and detail work is built east of the building, and a fingerprint of the model is compared
when a level ends. Without the model open, every level sets up a simplified stand-in.
Numbers in tutorial text and feedback always use a decimal point (0.024, never 0,024).
Each tutorial also has a challenge card (prepare the input yourself); they are kept in the
code but not in the chapter for now.

Code: `Lessons/LessonCatalog.cs` (the chapter), `Tutorials/Content/Cards.cs` (the cards),
`Tutorials/Content/Shapes.cs` (geometry from the model), `Tutorials/Evaluators/CardChecks.cs`
(the live checks), `Tutorials/TutorialLevels.cs` (set-up, Run), `Tutorials/TutorialHud.cs`
(the viewport HUD), `UI/LessonCanvas.Tutorial.cs` (the level page), `UI/TutorialDemos.cs`
(the demos), `Fin/` (FinGotchi's cards, fonts, palette and pixel pet).

## Debug in VS Code (Mac and Windows)

1. Install the recommended extensions (VS Code prompts you): **C#** and **C# Dev Kit**.
2. Open the `RhinoGotchi` folder, go to Run and Debug, pick a configuration, press F5:
   - **Rhino 9 - Mac**: builds `net7.0` and starts `/Applications/Rhino 9.app`.
     Rhino 9 runs on .NET 10 and loads the `net7.0` build as is. Quit any
     running Rhino 9 first, or the new one won't pick up `RHINO_PACKAGE_DIRS`.
   - **Rhino 8 (.NET 7+) - Mac / Windows**: builds `net7.0` and starts Rhino 8
     (`/Applications/Rhino 8.app` on Mac, `C:\Program Files\Rhino 8` on Windows).
   - **Rhino 8 (.NET Framework) - Windows**: builds `net48` and starts Rhino 8 with `/netfx`.
3. Type `RhinoGotchi` in Rhino to open the panel. Breakpoints hit as you play.

Rhino finds the plugin through `RHINO_PACKAGE_DIRS`, which points at the Debug
build folder, so you don't install anything. Stop debugging (or quit Rhino)
before rebuilding, because Rhino locks the loaded `.rhp`.

If Rhino 8 is installed somewhere else, edit `program` in `.vscode/launch.json`.

## Debug in Visual Studio / Rider

`src/RhinoGotchi/Properties/launchSettings.json` has the same three profiles.
Pick one and press F5.

## RhinoOnTheStreet tutorial

Type `RhinoOnTheStreet` in Rhino. A floating Perspective view pops out over the
viewports, the camera flies down onto a ghosted street that ends at an archway,
and two lessons follow, played with Rhino's real commands:

1. **Curve**: type `Curve`, click the five coloured rings, press Enter.
2. **Arch**: `Line` for the left pillar, Enter to repeat Line for the right one,
   then `Arc`, `S` (Start option), and click start, end and crown.

Targets are colour-coded red → green → blue (the order of Rhino's X, Y, Z axes).
The rhino dances when a lesson is complete, dozes after 5 s without a click,
falls over when a lesson is incomplete (a missed ring, Enter too early, Esc),
and does its final dance if the whole run had zero misses. A finale walks it
through the arch into a blue horizon.

While it runs, Osnap is on with Point snap, and locked target points sit on a
`RhinoOnTheStreet` layer. Run `RhinoOnTheStreet` again for SkipIntro,
RestartLesson, ReplayFinale, RestartTutorial or Quit. Quit restores your Osnap
settings, removes the targets and closes the view; the street and arch stay.

A browser preview of the same tutorial is in `tutorial/RhinoOnTheStreet.html`.

## Cross-platform notes

- Keep code to RhinoCommon and Eto.Forms for UI. Avoid WinForms/WPF and
  `System.Drawing` APIs that only exist on Windows.
- Use `#if NETFRAMEWORK` for the rare spot where net48 and net7.0 differ.
- Never change the assembly `Guid` in `AssemblyInfo.cs` or the command `Guid`
  after shipping.
- RhinoCommon is referenced at `8.0.23304.9001` (the first Rhino 8 SDK) with
  `ExcludeAssets="runtime"` so the plugin loads in every Rhino 8 release and
  never ships its own copy of RhinoCommon.
